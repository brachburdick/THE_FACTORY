# THE_FACTORY v1.9.1 — Overview

## 1. How It Works

THE_FACTORY is a protocol for running software projects with AI agents. One operator (you) works with one default agent at a time. The agent loads a short constitution (`CLAUDE.md`, ~120 lines) at startup and pulls in two kinds of skills on demand:

- **Flow skills** define the SEQUENCE — what steps to follow for a given task type (debug, feature, refactor)
- **Domain skills** define the KNOWLEDGE — what patterns and constraints apply to a given technology area

There are no standing agent roles. No preambles to copy-paste. No startup prompts. The agent classifies the task from the trigger table, loads the matching flow + domain skills, and follows the prescribed phase sequence with gates between each phase.

**Three tiers of memory:**
- **Hot** — `CLAUDE.md` (always loaded, governs everything)
- **Warm** — Skill files (loaded when triggered, ~1-2KB each)
- **Cold** — Architecture docs, research findings, ADRs (loaded only by explicit request)

**Task state** lives in `.agent/tasks.jsonl` per project — queryable, structured, no markdown sprawl. Each task carries a `taskType`, `flowPhase`, and `gateStatus` showing exactly where work stands. When a session ends, the agent updates the tracker and discards scratch.

**Handoffs** between genuine domain boundaries use a JSON Schema envelope (with required `taskType` field), validated by script before delivery. The receiving agent loads the correct flow without re-classifying.

**Quality** is enforced by executable eval cases, not prose rules in documents. Flow routing accuracy, gate compliance, and behavior preservation all have eval cases.

## 4. Task Lifecycle (Single-Domain)

```
 YOU (operator)
  │
  │  "Fix the bridge reconnect logic"
  │
  ▼
 CLASSIFY ─────────────────────────────────────────────────
  │  Signal: "fix" → debug-flow
  │  Domain: "bridge" → beat-link-bridge.md
  │
  ▼
 FLOW: debug-flow (5 gated phases)
  │
  │  ┌─ Phase 1: REPRODUCE ─── Gate: failing test exists? ───┐
  │  │  Write/find a test that demonstrates the bug.          │
  │  │  tasks.jsonl: flowPhase="reproduce"                    │
  │  └────────────────────────────────────────────────────────┘
  │                          │ pass
  │  ┌─ Phase 2: ISOLATE ──── Gate: root function named? ────┐
  │  │  Read only failure-path files. Name the origin.        │
  │  │  (SCUE: if L3/L4, check DMX output state here)        │
  │  └────────────────────────────────────────────────────────┘
  │                          │ pass
  │  ┌─ Phase 3: DIAGNOSE ── Gate: root cause documented? ───┐
  │  │  Explain cause in 1-2 sentences before coding.         │
  │  │  3 failed attempts → STOP, escalate to operator.       │
  │  └────────────────────────────────────────────────────────┘
  │                          │ pass
  │  ┌─ Phase 4: FIX ─────── Gate: tests pass, no regress? ──┐
  │  │  Minimal change. No refactoring. No feature creep.     │
  │  └────────────────────────────────────────────────────────┘
  │                          │ pass
  │  ┌─ Phase 5: VERIFY ─────────────────────────────────────┐
  │  │  Update tasks.jsonl: status=complete, gateStatus=all  │
  │  │  File eval case if pattern likely to recur.            │
  │  └────────────────────────────────────────────────────────┘
  │
  ▼
 DONE — no session file created
```

## 6. When Things Go Wrong

```
 Convention violated repeatedly?
   1. Write eval case (.agent/evals/)     ← FIRST
   2. Add rule to skill or CLAUDE.md      ← SECOND (if needed)
   3. Never add rule without eval

 Agent skips a gate?
   1. Check .agent/evals/flows/ for existing eval case
   2. If none, write one targeting the specific gate violation
   3. Track gate violation rate in .agent/metrics/

 Wrong flow loaded?
   1. Check flow routing table signals in CLAUDE.md
   2. If ambiguous, refine trigger signals
   3. Track flow accuracy in .agent/metrics/

 Agent doesn't know something?
   1. Check trigger table → load domain skill
   2. Skill doesn't exist → check cold tier (docs/, research/)
   3. Still stuck → create new skill from findings

 Task blocked?
   1. Mark blocked in tasks.jsonl with reason + blocker ID
   2. Move to next unblocked task
   3. Query: scripts/tasks.sh blocked
```
